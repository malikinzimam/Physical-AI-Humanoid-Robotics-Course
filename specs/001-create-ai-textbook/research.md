# Research: Automated Textbook Generation Script

**Generated**: 2025-12-03

This document outlines the technical decisions for the script that will automate the Docusaurus book generation.

## 1. How to Parse the `requirements.md` file?

- **Decision**: Use the `remark` unified ecosystem for Markdown processing.
- **Rationale**: `remark` is a powerful and standard tool for parsing Markdown into an Abstract Syntax Tree (AST). This allows for robustly traversing the document structure (headings, lists, etc.) to identify modules and topics, which is more reliable than using regular expressions. The `unist-util-visit` utility will be used to easily find and process specific nodes (like headings) in the tree.
- **Alternatives considered**:
  - **Regular Expressions**: Rejected as it is brittle and would easily break if the `requirements.md` formatting changes slightly.
  - **`marked` library**: A viable alternative, but `remark`'s ecosystem and plugin architecture are more powerful for complex structural analysis.

## 2. How to Generate Files and Directories?

- **Decision**: Use the native Node.js `fs/promises` module.
- **Rationale**: The built-in `fs` module is sufficient for creating directories (`mkdir`) and writing files (`writeFile`). The `promises` version allows for modern `async/await` syntax, making the script cleaner and easier to read. No external libraries are needed.
- **Alternatives considered**: None, as the native module is the standard and best practice.

## 3. How to Update the Docusaurus Sidebar?

- **Decision**: The script will programmatically generate a JavaScript object representing the sidebar structure and write it to `my-book/sidebars.js`.
- **Rationale**: Docusaurus sidebars are defined in a JS file. The script will build a nested object that matches the Docusaurus format for autogenerated sidebars (e.g., `{type: 'category', label: 'My Category', items: [...]}`). This object will be converted to a string and written to `sidebars.js`, overwriting the existing `tutorialSidebar`.
- **Alternatives considered**: Manually creating the sidebar. Rejected as it defeats the purpose of automation.

## 4. How to Invoke the Gemini CLI for Content Generation?

- **Decision**: Use the native Node.js `child_process.execSync` function.
- **Rationale**: `execSync` allows the script to call the Gemini CLI as a synchronous shell command. Since content for each page is generated one by one, a synchronous call is simple and effective. The output (generated text) from the CLI can be captured directly into a variable and written to the appropriate Markdown file.
- **Alternatives considered**:
  - **`spawn`**: More complex, intended for streaming large amounts of data. Overkill for this use case.
  - **Direct API integration**: Would require managing API keys and HTTP requests, whereas using the CLI abstracts this away, as per the user's request.
